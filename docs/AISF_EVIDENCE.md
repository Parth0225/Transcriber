### Requirement index

- **R1** [requirement] The system shall be a web application accessible via standard desktop and mobile browsers.
- **R2** [requirement] Only a single user role, "Meeting owner", shall exist in the first release, allowing upload, review, correction, and download of transcripts.
- **R3** [requirement] Each user shall only see meetings and transcripts that they own; no sharing between users is permitted.
- **R4** [requirement] A user shall be able to create a meeting with a required title (max 200 characters), optional date, and optional participant list (max 50 participants, each max 100 characters).
- **R5** [requirement] Meetings shall be listed in reverse chronological order showing title, date, and transcript status.
- **R6** [requirement] A user shall be able to edit or delete a meeting; deletion shall permanently remove its recording, transcript, and related text after confirmation.
- **R7** [requirement] A user shall be able to upload one recording per meeting; supported formats are MP3, WAV, M4A, MP4; maximum size 200 MB and maximum duration 3 hours.
- **R8** [requirement] If an uploaded file is unsupported or exceeds limits, the system shall display a clear error message indicating the problem.
- **R9** [requirement] Before transcription starts, the user shall select the spoken language of the meeting.
- **R10** [requirement] A user shall be able to replace a meeting's recording, which triggers a new transcription while optionally retaining the previous transcript per user request.
- **R11** [requirement] Transcription shall be initiated with a single action and run asynchronously; transcript status values are waiting, in progress, ready, failed.
- **R12** [requirement] The UI shall automatically refresh meeting list and meeting page to reflect current transcription status without user reload.
- **R13** [requirement] If transcription fails, the system shall display the failure reason in plain language and allow the user to retry with one action.
- **R14** [requirement] The generated transcript shall cover the entire recording, be split into lines each with a start time, optional speaker label, and spoken text; line length max 5,000 characters.
- **R15** [requirement] Users shall be able to view, edit text of any line, rename a speaker (propagating to all lines of that meeting), and search within a transcript or across all meetings.
- **R16** [requirement] Users shall be able to download the transcript as a .txt file with optional inclusion of timestamps and speaker names; file name shall be '<date>-<title>.txt' and header must follow specified layout.
- **R17** [requirement] The downloaded text file must be UTF‑8 encoded and open correctly in any basic text editor, preserving accents and non‑English characters.
- **R18** [requirement] Users shall be able to copy the entire transcript to the clipboard from the screen.
- **R19** [requirement] All delete operations shall require user confirmation before permanent removal.
- **R20** [requirement] The system shall maintain confidentiality: recordings and transcripts are only visible to their owning user and never to others.
- **R21** [requirement] If a server or network error occurs, the UI shall show a friendly message and preserve any in‑progress edits.
- **R22** [requirement] The UI shall be fully operable via keyboard, use readable text, and meet sufficient colour‑contrast standards.
- **R23** [requirement] Opening a transcript of up to 3 hours shall be responsive, using pagination or sections rather than rendering the entire transcript at once.
- **R24** [assumption] A speech‑to‑text service will be integrated, but the specific provider and payment model are not yet decided.
- **R25** [assumption] At launch the application will support at least English language transcription; additional languages are pending decision.
- **R26** [assumption] User authentication will require an account with a password from day one, though multi‑device sign‑in is undecided.
- **R27** [assumption] Retention policy for original audio files after transcription is undecided; system must be able to delete or keep them per future configuration.
